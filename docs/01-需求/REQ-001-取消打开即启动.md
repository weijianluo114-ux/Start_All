# REQ-001 · 取消「打开即启动」

- **状态**：已完成
- **提出日期**：2026-10-19
- **目标版本**：v1.2.0
- **关联**：FEAT-002、T-001

## 背景

原程序会把「上次使用的预设」写进 `last_used`，并在主窗口构造完成后用
`QTimer.singleShot(300, self.auto_launch_last_preset)` 触发一次自动启动。

结果：只要上次退出时列表里有程序，下一次双击 exe 就会**立刻把所有程序拉起来**。用户希望在双击只打开界面，
由自己决定何时启动。

## 期望行为

1. 双击 exe 只显示启动器窗口，不启动任何程序、文件夹。
2. 只有点击「🚀 一键启动」才运行列表内条目。
3. 旧配置文件里的 `settings.auto_launch` 不得再产生效果。

## 不在本次范围

- 不做"启动后延迟自动运行"之类的替代开关。
- 不改动预设切换（`on_preset_changed`）时的行为。

## 验收标准

- [x] 预置 `auto_launch: true` 的配置 + 探针程序，打开窗口后空转 3.5s，探针未被执行
- [x] 点击「一键启动」后探针被执行（证明启动能力未受损）
- [x] 「设置」菜单与其勾选项不再存在
- [x] 对照实验：改造前基线会误启动，改造后不会

## 实现要点

彻底移除整条通路（而非加开关）：

| 位置 | 处理 |
|---|---|
| `__init__` 末尾 `QTimer.singleShot(300, ...)` | 删除 |
| 「设置」菜单 + `QAction` | 删除 |
| `toggle_auto_launch()` / `auto_launch_last_preset()` | 删除 |
| `save_config` / `load_config` 的 `auto_launch` 字段 | 不再读写 |
| `QAction` 导入 | 移除 |

`settings` 容器保留（为空对象），供后续功能（如"上次浏览的文件夹"）复用。

## 决策记录

| 日期 | 议题 | 结论 | 理由 |
|---|---|---|---|
| 2026-10-19 | 是加开关还是删功能 | 删除 | 用户明确不要该能力，留开关会留下可被调用的入口 |
| 2026-10-19 | 旧配置怎么处理 | 忽略字段 | 避免用户手动删配置；下次保存自动清除 |
