# REQ-004 · 多文件夹合并到单窗口

- **状态**：**已回退（v1.6.0）** —— 自建窗口方案不满足用户要求，代码已移除
- **提出日期**：2026-10-19
- **完成日期**：2026-10-19（v1.5.0 实现）→ 2026-10-19 回退（v1.6.0）
- **关联**：REQ-003、FEAT-005、FEAT-006（已下线）、Q-002、T-005（已作废）

## 背景

预设里放了多个文件夹时，点「一键启动」会逐个调用系统接口打开，结果是**每个文件夹弹一个资源管理器窗口**，
任务栏迅速堆满。用户希望"在一个窗口里多开不同的文件夹"。

## 用户目标（回退原因）

需求原话是「**我确实只是需要在资源管理器中打开，不需要你新建一个窗口**」。
即：必须由 **Windows 资源管理器**承载标签页，而不是启动器自建一个仿资源管理器的窗口。

v1.5.0 采用的方案 D（应用内 Qt 多标签窗口）虽然达成了"一个窗口多个文件夹"，
但**不是资源管理器**，没有复制/粘贴、右键菜单、预览窗格等原生能力，因此判定为方向错误，已整体回退。

## 方案对比与实测结论

详见 `04-问题/Q-002-文件夹无法合并到资源管理器标签页.md`。摘要：

| 方案 | 可行性（含本机实测） | 结论 |
|---|---|---|
| **A. 调用资源管理器原生标签页** | 无 CLI / COM 接口；`OpenFolderInNewTab=1` 实测无效；`opennewtab` 动词实测开新窗口 | ✗ **不可用**（微软已暂停该功能推送） |
| **B. `.library-ms` 聚合目录** | 可单窗口，但内容是混在一起的条目 | ✗ 否决：不是"多个文件夹"，且会改动用户库 |
| **C. 第三方工具（如 ExplorerTabUtility）** | 由外部工具把新窗口收成标签，**仍是资源管理器** | ⚠ 可行但需用户自行安装，未集成 |
| **D. 应用内多标签窗口（Qt）** | 完全可控、无依赖 | ✗ **已回退**：不是资源管理器，不符合要求 |

## v1.5.0 实现（已被 v1.6.0 移除，仅存档）

- `FolderTab`：地址栏 + `QTreeView` + `QFileSystemModel`。
- `FolderTabsWindow`：`QTabWidget` + 底部「全部用资源管理器打开」。
- `_launch_worker()` 收集文件夹后经 `folders_requested` 信号回主线程合并。
- 已知坑：`QFileSystemModel` 必须 `setRootPath()` 才会真正扫描目录，共享模型会导致列表恒空。

## 回退后的行为（v1.6.0 起）

- 预设中**每个文件夹**都由系统资源管理器打开（一次启动 N 个文件夹 = N 个资源管理器窗口）。
- 程序条目行为不变；失效路径仍跳过。
- 代码层面删除了 `FolderTab` / `FolderTabsWindow` / `folders_requested` 信号 / `_folder_window`，
  并清理了 `QTabWidget`、`QTreeView`、`QFileSystemModel`、`QLineEdit`、`QHeaderView`、`pyqtSignal` 等导入。

## 后续可选方向

若确实要"资源管理器内多标签"，只能走方案 C：由用户安装 ExplorerTabUtility 之类的工具，
启动器照常逐个调用系统打开，工具在后台把新窗口并入已有窗口的标签。
是否集成（例如启动时检测工具是否在运行并提示）待用户决定，**未擅自实现**。
