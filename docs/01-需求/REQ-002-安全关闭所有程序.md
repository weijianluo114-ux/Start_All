# REQ-002 · 关闭所有程序前确认 + 运行状态检测

- **状态**：已完成
- **提出日期**：2026-10-19
- **目标版本**：v1.3.0
- **关联**：FEAT-003、T-002

## 背景

原「⏹ 关闭所有程序」直接对 `launched_items` 里记录的进程执行 `taskkill /f /t`，并紧接着 `self.close()`：

1. **没有确认**，误点即批量强杀，正在编辑的文件可能直接丢失；
2. 只处理"本次会话内由启动器拉起的进程"，若程序是用户手动打开的，按钮对它无效；
3. 对已退出/未启动的条目也照发 `taskkill`，产生无意义的失败调用。

## 期望行为

1. 点击后**先弹确认框**，列出将要关闭的程序；默认焦点在「否」。
2. 用户点「否」→ 什么都不做。
3. 点「是」→ 逐项**检测是否正在运行**：正在运行才关闭，未运行/无法判定的跳过。
4. 关闭完成后给出结果汇总（关闭数、跳过数、失败项）。
5. **不退出启动器**，可以继续操作。

## 决策记录

| 日期 | 议题 | 结论 | 理由 |
|---|---|---|---|
| 2026-10-19 | 关闭范围 | 列表内**全部**条目（不限本次会话） | 用户需要"手动打开的程序也能一键关掉" |
| 2026-10-19 | 关闭后是否退出 | 不退出 | 需要反复启停，退出会打断工作流 |

## 验收标准

- [x] 有程序运行时必须弹确认框，正文含"正在运行"与程序名
- [x] 点「否」→ 目标进程存活
- [x] 点「是」→ 目标进程被关闭，且提示"已关闭 N 个"
- [x] 未运行的条目被跳过，并在提示中体现
- [x] 列表内全部未运行时，直接提示"无需关闭"，不再弹确认框
- [x] 关闭后启动器窗口仍然存在（未被 `close()`）

## 实现要点

`terminate_all_and_exit()` → 重命名为 `close_all_programs()`，拆成四个职责单一的方法：

| 方法 | 职责 |
|---|---|
| `_get_process_map()` | `tasklist /fo csv /nh` → `{镜像名小写: {pid…}}`（用 `csv` 解析，兼容带逗号的路径） |
| `_close_targets(paths)` | 列表条目 → `(原路径, 镜像名)`；文件夹与非 `.exe/.com` 的脚本类镜像名为 `None` |
| `_find_launched(path)` | 在 `launched_items` 里按规范化路径找回本次启动记录（可拿到精确 PID） |
| `_kill_target(path, image)` | 三级关闭：记录的 PID → 镜像名 `/im` → `special_kill_map` 伴生进程 |

判定顺序（对每个条目）：
1. 本次会话启动过且 PID 仍在 → 直接算"运行中"（最精确）
2. 镜像名为 `None`（`.bat/.cmd`）且非本次启动 → 跳过，理由"无法判定"
3. 镜像名等于启动器自身 → 跳过，避免自杀
4. 镜像名出现在进程快照中 → 运行中
5. 其余 → 跳过，"未运行"

关闭后重新采集一次进程快照做**二次校验**：镜像名仍在 → 记入"关闭失败"。

## 已知限制

- `.bat/.cmd` 条目若不是在本次运行中启动的，无法按镜像名判定（其进程名是 `cmd.exe`），会被跳过。→ 见 Q-001
- 按镜像名关闭会命中**同名全部实例**（例如列表里一个 `chrome.exe` 会关掉所有 Chrome 进程）。这是 `/im` 的固有语义，属于预期行为。
