# REQ-014 · 界面多语言（简体中文 / English / 日本語 / 繁體中文）

- **状态**：已完成（v1.14.0）
- **提出**：2026-10-21
- **目标版本**：v1.14.0
- **关联**：FEAT-014、REQ-011（字体）、REQ-012（全局字体）、T-015

## 背景

程序原本只有简体中文界面。随着使用者在英语国家出现，非中文用户拿到程序后
**连"添加文件夹"和"关闭"都分不清**：主界面六个胶囊、设置面板、关闭确认窗体全是中文，
而关闭确认是"不可恢复"的操作，看不懂就等于不敢按。

同时 README 只有中文，外部使用者不知道该从 Releases 下哪个文件、该怎么构建。

## 期望行为

1. 设置面板里能选**界面语言**，至少四种：简体中文（默认）、English、日本語、繁體中文；
2. 选择后**立即生效**，不必重启；偏好写入配置，下次启动保持；
3. 主界面（标题、预设行、六个胶囊、圆盘提示）、设置面板、所有对话框与确认窗体
   全部跟着换语言；列表类型提示（文件夹 / 文件 / 路径不存在）也要换；
4. 换语言不能破坏既有状态：**不能在改动后关不掉刚打开的文件**（v1.12.0 的教训：
   重建主窗口会丢 `launched_items` 里的文件类条目 PID）；
5. 语言名在列表里用**原生写法**（English / 日本語），不随当前语言翻译；
6. 圆盘上的"启动 / 关闭"：中日文竖排两字，英文必须换成横排整词
   （`START` 竖排要 5 个字高，必然顶出鱼身）；
7. 任何语言、11px / 17px 两端字号下都不重叠、不越界、不裁字；
8. README 补一节英文说明，并在顶部说明"默认中文，可在设置里切换语言"。

## 不在本次范围

- 不重建窗口 / 不重开设置面板（避免状态丢失与视线跳）；
- 不翻译**日志文件**（排障用的开发者信息，中文便于对照历史日志）；
- 不翻译预设方案的**名称**（那是用户数据，和文件名同性质）；
- 不做系统语言自动识别（默认简体，切一次就记住）；
- 不新增第 5 种语言，也不做翻译文件外置（译文进代码，跟着 exe 走）。

## 实现要点

| 项 | 做法 |
|---|---|
| 文案层 | 新文件 `src/lf_i18n.py`：`LANGUAGES` + `STRINGS[键][语言码]` + `Lang.CODE` + `t(键, **kw)` |
| 回落链 | 当前语言 → 简体中文 → 键名（漏翻只露中文，不白屏、不抛错） |
| 占位符 | 统一 `{}` + 关键字（`t('msg.path_missing', path=p)`），文案里的 `%USERPROFILE%` 原样保留 |
| 换语言 | `Lang.set()` → `SettingsDialog.retranslate()` + `LauncherWindow.retranslate_ui()`，不重建窗口 |
| 几何重算 | 胶囊 `setText` 后重算列宽 → 布局激活 → 窗口撑到新的最小尺寸（只放大不缩小） |
| 圆盘竖排/横排 | `_is_vertical_text()` 判断，`_layout_vertical()` / `_layout_horizontal()` 两套排法 |
| 持久化 | `settings.language`，在 `load_config()` 里**先于任何 t() 之前**恢复 |

## 决策记录

| 决定 | 理由 | 备选与否决原因 |
|---|---|---|
| 译文进代码而非外置 `.json`/`.po` | 单文件 exe 分发，外置文件会丢；117 条文案也不需要翻译协作流程 | 外置 json：打包要多带资源、用户删了就没界面 |
| 语言名用原生写法 | 母语用户找自己的语言靠母语写法 | 翻译成当前语言：英语界面里写"Japanese"，日本人反而要二次辨认 |
| 换语言不重建窗口 | 重建丢 `launched_items`（文件类条目的 PID），表现为"换完语言关不掉刚打开的文件" | 重建窗口最省事，但会引入一个难查的功能回归 |
| 设置面板就地 `retranslate()` | 用户正盯着面板操作，窗口闪一下会以为点错了 | 关掉重开：实测更"干脆"，但视线跳 |
| 日志不翻译 | 日志是排障用的，历史日志全是中文，混语言反而更难搜 | 翻译日志：工作量翻倍且价值低 |
| 英文圆盘文字横排 | `START` 竖排要 5 格 ≈130px，半条鱼只有 ~70px 高 | 缩字号到能竖排：会小到看不清 |
