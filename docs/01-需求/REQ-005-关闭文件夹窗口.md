# REQ-005 · 关闭列表内文件夹对应的资源管理器窗口

- **状态**：已完成
- **提出日期**：2026-10-20
- **目标版本**：v1.7.0
- **关联**：FEAT-007、Q-003、T-008

## 背景

v1.4.0 起支持文件夹条目，但「关闭」刻意跳过了文件夹——打开的是资源管理器窗口，不是进程。
结果是：一键启动打开 5 个文件夹、10 个程序后，程序能一键关掉，**文件夹窗口还得手动一个个关**。

用户提出：能否把"对应的文件夹也关闭"，并追问"如果我把这些窗口拖进同一个资源管理器窗口
合并成标签页，还能正常关闭吗"。

## 期望行为

1. 「关闭全部」在关闭程序之外，同时关闭列表内文件夹对应的资源管理器窗口。
2. 窗口内**所有标签都属于列表条目** → 直接整窗关闭，不再逐窗确认。
3. 窗口**混有列表外的标签** → 单独询问一次：同意则整窗关闭，不同意则跳过这些窗口，
   其余内容照常关闭。
4. 列表里的文件夹当前没有打开窗口 → 自然跳过，不报错，结果里说明数量。
5. **绝不结束 `explorer.exe`**：那会连带关掉任务栏和用户所有窗口。
6. 关闭动作与结果都要可追溯：每条写入日志，失败给出原因。
7. 文件夹关闭并入「关闭全部」同一个入口，不新增按钮（一次确认完成全部关闭）。

## 决策记录

| 日期 | 议题 | 结论 | 理由 |
|---|---|---|---|
| 2026-10-20 | 关闭粒度 | **整窗关闭**，不到标签页 | 系统没有"关闭指定标签"的稳定接口，见 Q-003 |
| 2026-10-20 | 混合标签窗口 | **询问用户**：同意整窗关，不同意跳过 | 不擅自连带关闭无关标签；用户明确要求"让我选择" |
| 2026-10-20 | 是否记录打开时的 HWND | **不记录** | 拖拽合并成标签后原 HWND 消失，基于 HWND 的记录必然失效 |
| 2026-10-20 | 入口 | 并入「关闭全部」既有确认流程 | 避免两套确认，减少误操作 |
| 2026-10-20 | 关闭消息 | `WM_CLOSE` 循环，不用 `Quit()` | 多标签窗口下 `Quit()` 实测无效，见 Q-003 |

## 验收标准

- [x] 列表内文件夹已打开 → 主确认框列出"文件夹窗口 N 个（整窗关闭）"，正文含窗口名
- [x] 主确认框点「否」→ 一个窗口都不关
- [x] 点「是」→ 对应窗口关闭，结果提示"已关闭 N 个文件夹窗口"
- [x] 列表外的资源管理器窗口不受影响（实测：无关窗口保持打开）
- [x] `explorer.exe` 保持运行，任务栏正常
- [x] 多标签窗口（含列表内 + 列表外标签）→ 单独询问；选「否」不关、选「是」整窗关闭
- [x] 真实 2 标签窗口可被整窗关闭（`attempts=2`，窗口消失）
- [x] 文件夹未打开 → 计入"未打开窗口"，提示「无需关闭」时不弹确认框
- [x] 每次判定与关闭动作写入日志

## 实现要点

| 位置 | 作用 |
|---|---|
| `list_explorer_windows()` | 枚举资源管理器窗口；同一窗口的多个标签合并为一条（`paths`） |
| `LauncherWindow._folder_window_plan()` | 按路径把列表条目对应到窗口，分为"可整窗关闭"与"混有列表外标签" |
| `LauncherWindow._close_folder_window()` | 整窗关闭：按标签数循环 `WM_CLOSE` 并复查 |
| `LauncherWindow.close_all_programs()` | 统一入口：程序 + 文件夹窗口，一次确认，分开汇总 |

关键点：路径统一经 `_norm_fs_path()` 归一化（大小写、尾部反斜杠、`::` 虚拟位置不参与匹配）。
