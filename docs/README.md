## 编号与状态

- 编号：`REQ-001` / `FEAT-001` / `BUG-001` / `Q-001`，三位数，**只增不改**。
- 作废的条目把状态改为「已废弃」而不是删除，保留决策轨迹。
- 日期统一 `YYYY-MM-DD`。
- 状态流转：`待确认` → `待实现` → `实现中` → `待验收` → `已完成`；异常分支 `搁置`、`已废弃`。

## 一次改动的标准流程

1. **先建需求**：在 `01-需求` 写清「期望行为」与「验收标准」，哪怕只有三行。
2. **再改代码**：改动尽量限定在该需求范围内，不做顺手重构。
3. **补功能文档**：若对外行为发生变化，更新或新建 `02-功能` 条目。
4. **写验收记录**：在 `06-测试` 追加用例（命令 + 结果，有对照实验更好）。
5. **记变更**：在 `03-变更日志` 记 Added / Changed / Removed / Fixed。
6. **关闭需求**：状态改「已完成」，写上关联的测试编号与版本号。

> 原则：**文档跟着行为走**。文档只描述「现在是什么样」，历史过程交给变更日志。
