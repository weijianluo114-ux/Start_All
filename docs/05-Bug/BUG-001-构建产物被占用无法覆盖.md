# BUG-001 · 构建产物被正在运行的实例占用，无法覆盖

- **状态**：已关闭（规避）
- **严重度**：轻微（不影响程序运行，只影响发布流程）
- **发现日期**：2026-10-19
- **影响版本**：v1.2.0 构建
- **修复版本**：v1.3.0（版本化命名）
- **关联**：构建与发布

## 现象

重复打包后，用 `cp` 把新的 exe 覆盖到已存在的旧 exe 上，报错：

```
cp: cannot create regular file '.../一键多启_rebuild.exe': Device or resource busy
```

用 `.NET` 独占打开同样失败：

```
The process cannot access the file because it is being used by another process.
```

但当时 `Get-Process -Name '一键多启'` 查不到任何进程，因此被误判为"无进程却占用"。

## 复现步骤

1. 构建并产出 `一键多启_rebuild.exe`
2. **双击运行它**（窗口保持打开）
3. 再执行一次构建，尝试用同名文件覆盖
4. 覆盖失败；等待 30 秒、重试 6 次仍失败

## 根因

**文件被正在运行的实例持有句柄**。Windows 上运行中的 exe 无法被替换/删除，这是预期行为，不是缺陷。

初次判断错误的原因值得记录：

```powershell
Get-Process -Name '一键多启'      # ← 精确匹配，匹配不到 "一键多启_rebuild"
```

修正后的查法（按路径模糊匹配，才能看到真实情况）：

```powershell
Get-Process | Where-Object { $_.Path -like '*一键多启*' } |
  Select-Object Id, ProcessName, Path, MainWindowTitle
```

结果暴露了 2 个路径为 `...\一键多启_rebuild.exe`、且带窗口标题的进程——占用源就是它。

## 规避方案

- **构建产物版本化命名**，不复用旧文件名：
  `一键多启_v1.2.0.exe`、`一键多启_v1.3.0.exe`…… PyInstaller 直接写新文件，天然避开占用。
- 覆盖前先确认无运行实例：用上面的**路径模糊匹配**查，不要用精确进程名。
- 仍需清理旧文件时：关闭实例后再删；若句柄残留，用
  `MoveFileEx(..., MOVEFILE_DELAY_UNTIL_REBOOT)` 登记重启删除。
- 验证构建时用**隔离的 `LOCALAPPDATA`** 启动，既不影响真实配置，也便于区分"测试实例"与"用户实例"。

## 回归验证

- v1.3.0 改为输出 `一键多启_v1.3.0.exe`（新文件名）后，构建一次成功，无占用报错。
- 同时确认：覆盖式命名（同名）在实例运行时**必然失败**，属于设计约束而非偶发问题。

## 经验

> 1. 排查"文件被占用"第一步是**找句柄持有者**，而 `Get-Process -Name` 是精确匹配，长名字容易漏。
> 2. 对 Windows 上的大体积单文件 exe，"覆盖式发布"本身就是脆弱操作；版本化文件名比反复重试更可靠。
> 3. 用户正在使用程序时，构建脚本不要去杀进程、删文件——**先确认再操作**。
