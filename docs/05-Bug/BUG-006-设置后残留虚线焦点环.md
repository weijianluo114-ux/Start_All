# BUG-006 · 点击「设置」后胶囊上残留一圈虚线

- **状态**：已修复（v1.14.1）
- **发现**：2026-10-21
- **影响版本**：v1.11.0 ~ v1.14.0
- **关联**：FEAT-009、FEAT-011、T-017

## 现象

点过主界面右下角的「设置」胶囊之后，那枚胶囊内侧留下一圈**金色虚线**，
直到点别的地方才消失。截图见 `docs/images/bug-006-before.png`：

```
┌────────────────┐
│ ╭ ─ ─ ─ ─ ─ ─ ╮ │
│ ┆    设置    ┆ │   ← 内侧金色虚线环
│ ╰ ─ ─ ─ ─ ─ ─ ╯ │
└────────────────┘
```

同样的虚线也出现在：

- 设置面板里点过的「开机自启动」开关（点线框）；
- 拖动过「字号」滑块之后，滑块周围（虚线框）。

## 复现

1. 打开启动器；
2. 用鼠标点一下「设置」胶囊（不要用 Tab）；
3. 松手 → 胶囊内侧出现金色虚线环，鼠标移开也不消失。

## 根因

三个自绘控件都画了**键盘焦点环**，判据只用了 `hasFocus()`：

```python
if enabled and self.hasFocus():        # ← 鼠标点出来的焦点同样满足
    pen.setStyle(Qt.DashLine)
    ...
```

`QPushButton` / `ToggleSwitch` / `SizeSlider` 的焦点策略都是 `Qt.StrongFocus`，
鼠标点击**也会**把焦点给控件——于是"点了就有虚线"，而且只要焦点不离开就一直挂着。

焦点本身是正常的（键盘用户需要它）；问题在于**没有区分焦点来源**，
也没有区分"提示键盘用户"和"装饰鼠标用户"这两种用途。

## 修复

### 1. 记住焦点来源

三个控件各加一个状态位 `_kb_focus`，在 `focusInEvent` 里按 `event.reason()` 判定：

```python
_KB_FOCUS_REASONS = (Qt.TabFocusReason, Qt.BacktabFocusReason, Qt.ShortcutFocusReason)

def focusInEvent(self, event):
    self._kb_focus = event.reason() in _KB_FOCUS_REASONS
    self.update()
    super().focusInEvent(event)

def focusOutEvent(self, event):
    self._kb_focus = False
    self.update()
    super().focusOutEvent(event)
```

被排除的 reason：

| reason | 场景 | 为什么不算 |
|---|---|---|
| `MouseFocusReason` | 鼠标点击 | 点完就留框，最扎眼 |
| `ActiveWindowFocusReason` | 切回窗口 | 不是键盘导航，回来就出现一圈框很突兀 |
| `PopupFocusReason` | 下拉框关闭后回焦 | 同上，属于被动获得 |

判定收敛成模块级 `_keyboard_focused(widget)`，三处绘制共用一套规则，
避免以后再各自实现一遍、又走岔。

### 2. 虚线段全部移除

`Qt.DashLine` / `Qt.DotLine` → `Qt.SolidLine`，透明度从 165 降到 130。
键盘用户仍然看得见"焦点在这"，但它是**一圈极淡的实线内环**，不再是虚线段。
`tests/test_step16_focus_ring.py` 会扫源码，`DashLine` / `DotLine` 出现 0 次才算通过。

## 备注

`setFocus()` 对**已有焦点**的控件不再发 `FocusIn`，焦点来源不会更新。
测试里必须先 `clearFocus()` 再 `setFocus(TabFocusReason)`；
真实场景按 Tab 是"移走再移回"，一定会触发 `FocusIn`，不受影响。
