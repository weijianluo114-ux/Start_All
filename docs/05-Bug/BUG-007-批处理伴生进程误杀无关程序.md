# BUG-007 · 批处理脚本的伴生进程会把无关程序算进去

- **状态**：已修复（v1.14.2）
- **发现**：2026-10-21（外部扫描反馈，见文末）
- **影响版本**：v1.0.0 ~ v1.14.1
- **关联**：FEAT-002、FEAT-003、T-018

## 现象

预设里有一条 `.bat`。点左半圆启动它，**在这之后的两秒内**用户又手动打开了一个程序
（浏览器、编辑器、别的脚本……都没关系）。

此时点右半圆「关闭全部」并确认，那个**根本不在预设里**的程序会被强制结束，
任务管理器里删得干干净净，未保存的工作直接丢失。

## 复现

1. 预设里加一个 `demo.bat`，内容 `@echo off` + `timeout /t 10`；
2. 点左半圆启动；
3. 两秒内手动打开任意程序（例：记事本、浏览器）；
4. 点右半圆 → 确认。

结果：第 3 步打开的程序被结束。

## 根因

`_launch_worker` 对 `.bat` / `.cmd` 用**全局 PID 差集**来猜"脚本启动了哪些进程"：

```python
before = self._get_all_pids()          # 整个系统的 PID 快照
result = launch_program(path)
time.sleep(2)
after = self._get_all_pids()
extra_pids = list(after - before)      # ← 这 2 秒内"新出现的一切"
```

差集只回答"哪些 PID 是新的"，**不回答"谁启动的"**。所以这两秒里任何进程启动——
用户手动开的程序、Windows 后台任务、别的软件自更新——都会被记成这个脚本的伴生进程，
进入 `launched_items` 的第 4 项；关闭时 `_kill_target` 对它们逐个
`taskkill /f /t /pid`，没有任何归属校验。

实测复现（`tests/test_step17_bat_spawn_safety.py`，同一时刻只启动了一个无关程序）：

```
[3] 旧算法（全局差集）收进来 7 个 PID：[8084, 9864, 9912, 13344, 15668, 21672, 25336]
    其中 9912 就是那个无关程序
```

7 个里只有 2 个真正属于脚本（ping 与它的 conhost），其余 5 个全是系统噪声。

## 修复

### 1. 归属判据换成父子链

新增 `process_snapshot()`（WMI 一次取全量 `ProcessId / ParentProcessId / Name / CreationDate`）
与 `descendants_of(root_pid, snapshot)`：从脚本进程（cmd）出发，按 `ParentProcessId`
逐层扩展，只收**父链可达**的进程。

Windows 在父进程退出后仍保留子进程里记录的 `ParentProcessId`，所以脚本跑完了也照样能回溯。

```python
kids = descendants_of(root_pid, after)   # 只认父子链
```

同一个测试里新算法的结果：

```
[4] 新算法（父子链）收进来 2 个 PID：[(21672, 'PING.EXE'), (25336, 'conhost.exe')]
    无关程序 9912 不在其中
```

### 2. 关闭前再验一次"还是同一个进程"

脚本退出后，它的 **PID 会被系统复用**；此时按 PID 关闭就会杀掉一个毫不相干的新进程。
因此记录伴生进程时同时存下 `(镜像名, 创建时间)`：

```python
launched_items.append((proc, resolved, preset, extra_pids, {pid: (name, created)}))
```

关闭时 `_spawn_still_same()` 逐个核对：PID 不存在 → 跳过；镜像名或创建时间不符 →
判定为 PID 复用，跳过并写日志。光看镜像名不够——`cmd.exe` / `python.exe` 这种同名进程到处都是。

### 3. 拿不到证据时不记录

- 启动后没拿到 cmd 的 PID（`launch_program` 返回 None）→ 记录为空；
- WMI 快照读取失败 → 记录为空；
- `pywin32` 缺失 → 关闭侧直接跳过。

以前这些情况会退化成"差集照用"，现在一律**宁可少关，不可错杀**。

### 4. 系统外壳黑名单

`PROTECTED_IMAGES`（explorer / csrss / winlogon / svchost / dwm / RuntimeBroker …）
即使因异常被归到脚本名下也绝不结束。父子链正常时它们根本不会出现在结果里，
这层只是"最坏情况也不至于杀掉桌面"。

## 行为差异（属修复，非回归）

| 场景 | v1.14.1 | v1.14.2 |
|---|---|---|
| 窗口期内用户打开别的程序 | 被记成伴生进程，关闭时被杀 | 不记录、不关闭 |
| 脚本通过 `start` 启动的程序 | 能关 | 能关（父子链可达） |
| 脚本通过 `explorer` 中转打开的程序 | 能关（差集侥幸命中） | **不记录**（父链断开，无法证明归属） |
| 拿不到 cmd PID 时 | 仍按差集记录 | 不记录 |
| PID 被复用 | 直接杀，可能误杀 | 校验镜像名与创建时间，不符则跳过 |

第三行是这次修复的代价：`start "" "某个文档"` 这类经 ShellExecute 转交的条目，
进程的父是 explorer 而不是 cmd，父子链无法证明归属，因此不再关闭。
按"安全优先"原则接受该退化——**少关一个可以手动处理，错杀一个会丢数据**。

## 验证

`tests/test_step17_bat_spawn_safety.py`（T-018）：父子链纯逻辑、真实 bat + 无关程序、
PID 复用跳过、正确记录可关闭、无 cmd PID 不记录，全部通过。
真实 exe 端到端：日志 `脚本 demo.bat：cmd pid=…，归属到 2 个伴生进程`，无关键不在其中。
