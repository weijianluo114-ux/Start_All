# BUG-003 · 关闭程序时连续闪现控制台黑框

- **状态**：已修复（v1.6.1）
- **报告日期**：2026-10-20
- **影响版本**：v1.2.0 ~ v1.6.0（所有引入"关闭所有程序"的版本）
- **关联**：FEAT-003（安全关闭）、BUG-002（关闭健壮性）

## 现象

点击「⏹ 关闭所有程序」并确认后，屏幕上连续闪出**多个黑色控制台窗口**，
数量随列表内程序个数增加而增多。功能本身正常，但观感差、且会抢走焦点。

## 根因

程序以 PyInstaller `--windowed` 打包，进程**没有控制台**（子系统为 GUI）。
在这种宿主下用 `subprocess` 调用控制台程序（`taskkill.exe`、`tasklist.exe`），
Windows 会为每个子进程**新建一个控制台窗口**，子进程退出即消失——表现为"闪一下"。

关闭流程本身就是多次调用：

```
_get_process_map()        → tasklist      （1 次）
每个条目 _pid_info()      → tasklist      （N 次）
每个条目 _kill_target()   → taskkill …    （1~3 次/条）
_wait_until_gone()        → tasklist 轮询 （0.25s 一次，最多 3 秒）
```

因此一次关闭会拉起十几个到几十个子进程，黑框接连出现。

另有一处放大因素：`_get_all_pids()` 与 `_get_process_map()` 原本写成
`subprocess.check_output('tasklist /fo csv /nh', shell=True)`，
`shell=True` 会先起 `cmd.exe`，于是又多一层窗口。

## 修复

新增统一封装 `hidden_subprocess_kwargs()`：

```python
_CREATE_NO_WINDOW = 0x08000000

si = subprocess.STARTUPINFO()
si.dwFlags |= subprocess.STARTF_USESHOWWINDOW
si.wShowWindow = 0                      # SW_HIDE
return {'creationflags': _CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP,
        'startupinfo': si}
```

应用到全部 5 处调用点：

| 位置 | 用途 |
|---|---|
| `ShellProc.kill()` | `taskkill /f /pid` |
| `_get_all_pids()` | 启动 .bat 时采集 PID 差集 |
| `_get_process_map()` | 关闭前/复查时的进程快照 |
| `_taskkill()` | 所有实际的 taskkill |
| `_pid_info()` | 核对单个 PID 是否存活 |

同时把两处 `shell=True` 改为参数列表调用，去掉 `cmd.exe` 这一层。

提权路径（`_elevated_kill`）原本就用 `ShellExecuteW(..., nShowCmd=0)`，即 `SW_HIDE`，
保持不动；该路径只在"拒绝访问"时才触发，且本身会弹 UAC。

## 验收

`tests/test_step6_no_console_flash.py`，**必须用 `pythonw.exe` 运行**（宿主无控制台，
否则子进程继承控制台，测不出新建窗口这件事）。

| 步骤 | 内容 | 结果 |
|---|---|---|
| 0 | 宿主控制台句柄 | `0` ✅ |
| 1 | 参数含 `CREATE_NO_WINDOW` 与 `SW_HIDE` | `creationflags=0x08000200` ✅ |
| 2 | 对照组（不加隐藏参数）起一个存活 5 秒的 ping | 控制台窗口 `4 → 6`（+2）✅ 证明测试能看见黑框 |
| 3 | 实验组（隐藏参数）同样起 ping | 控制台窗口 `4 → 4`（+0）✅ |
| 4 | 隐藏参数下 `tasklist` | 正常返回自身 PID ✅ |
| 5 | 隐藏参数下 `taskkill` 不存在的 PID | `rc=128 not found` ✅ 功能未受影响 |

回归：T-001 ~ T-004 全通过（关闭流程本身未改变，仅隐藏子进程窗口）。

### 打包产物端到端（v1.6.1 实测）

用隔离配置放一个**真实运行中的 GUI 探针**（启动器 exe 的副本，本身不带控制台），
通过 UI 自动化点击「⏹ 关闭所有程序」→ 确认框点 `Yes`，随后每 100ms 采样一次控制台窗口：

```
DIALOG_FOUND|pid=31968
BASE_CONSOLE=5
PROBE_BEFORE=2
CLICK=Yes
MAX_CONSOLE=5
DELTA=0
SAMPLES_OVER_BASE=0
PROBE_AFTER=0
```

配套日志证明真的执行了关闭（不是"没关所以没黑框"）：

```
taskkill /f /t /pid 13704 → rc=0 SUCCESS: ... PID 18020 ... terminated. | PID 13704 ... terminated.
taskkill /f /t /im LFTEST_T7APP.exe → rc=128 ERROR: The process "LFTEST_T7APP.exe" not found.
关闭结束：成功 1，失败 0，跳过 0
```

即：**确实杀了进程（rc=0），但全程没有新增任何控制台窗口（DELTA=0）**。

## 已知残余

- 若走到"需要管理员权限"的提权分支，UAC 弹窗是系统界面，无法也不应隐藏；
  其后的 `cmd.exe` 以 `SW_HIDE` 启动，正常情况下不出现黑框。
- 用户自己添加的 `.bat` / `.cmd` 条目仍以 `CREATE_NEW_CONSOLE` 启动，
  这是**有意为之**（批处理需要可见窗口），不属于本缺陷范围。

## 排查方法（可复用）

判断"某个子进程是否会弹黑框"，最可靠的做法不是肉眼观察，而是：

1. 用 `pythonw.exe` 启动测试宿主，确认 `GetConsoleWindow() == 0`；
2. 让被测子进程活久一点（例如 `ping -n 6`），避免窗口来不及统计；
3. `EnumWindows` 统计类名含 `Console` / `PseudoConsole` / `CASCADIA` 的顶层窗口；
4. 同参数**跑一次对照组**，若对照组也没有新增窗口，说明方法本身失效，结论不成立。
