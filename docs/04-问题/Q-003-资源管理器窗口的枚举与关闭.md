# Q-003 · 资源管理器窗口的枚举与关闭语义

- **状态**：已定位（v1.7.0 依据此结论实现 FEAT-007）
- **日期**：2026-10-20
- **关联**：REQ-005、FEAT-007

## 问题

"关闭列表内文件夹"没有系统级接口——Windows 没有"关闭某个文件夹"的 API，只有"关闭窗口"。
需要先确认三件事：

1. 能否枚举资源管理器窗口并拿到它显示的**路径**？
2. 多标签窗口（Win11 把多个文件夹拖进同一窗口）在接口里长什么样？
3. 用哪个动作关闭才可靠？会不会误杀 `explorer.exe`（连带关掉任务栏）？

## 实测结论（Windows 11，受控临时目录，未触碰用户窗口）

| 实验 | 结果 |
|---|---|
| `Shell.Application.Windows()` 枚举 | 3 个真实窗口全部可见，能取到 `HWND` 与 `Document.Folder.Self.Path` |
| "主文件夹"这类虚拟位置 | 路径返回 `::{F874310E-B6B7-47DC-BC84-B9E6B38F5903}`，**不含盘符，不会误匹配真实路径** |
| 单标签窗口按路径匹配 + `Quit()` | 关闭成功；其余窗口完好；`explorer.exe` 存活 |
| 2 个标签的窗口 | 在接口里表现为**同一 HWND 的 2 条条目**，各自带自己的路径；**后台标签同样可见** |
| 多标签窗口下 `Quit()` | **无效**：不抛异常，也不产生任何变化 |
| 多标签窗口下 `WM_CLOSE` | **只关闭当前活动标签**（条目 2 → 1，窗口仍在）；连发才整窗消失 |
| 真实 2 标签窗口整窗关闭（v1.7.0 实现） | `_close_folder_window` 返回 `True`，`attempts=2`，窗口消失，`explorer.exe` 存活 |

## 结论

1. **可按路径判定**：能知道某文件夹当前是否被打开、在哪个窗口、该窗口还有几个标签。
2. **只能整窗关闭**：没有"关闭指定标签"的稳定接口（UIA 按标签点击可以做到，但依赖 UI 自动化，
   版本变动即失效，且要抢焦点，不采用）。
3. **关闭用 `WM_CLOSE` 循环**，不用 `Quit()`（多标签下无效）。
4. **绝不用 `taskkill /im explorer.exe`**：那会关掉任务栏和用户所有窗口。

## 对设计的直接影响

- **不记录"打开时的 HWND"**：用户把窗口拖进另一窗口合并成标签后，原窗口的 HWND 消失，
  任何基于 HWND 的记录都会失效。改为**关闭时现场重新枚举**、按 `HWND` 分组、按路径判定。
- **混合标签窗口必须问**：整窗关闭会连带关掉列表外的标签，需要用户明确同意。
- **"未找到窗口"是正常结果**：文件夹没打开、或开着但被合并进别的窗口后又被关掉，都应跳过。

## 遗留

- 若将来 Windows 提供稳定的标签级接口（或 UIA 方案足够可靠），可升级为"只关指定标签"，
  此时本节结论与 FEAT-007 的"整窗关闭"约束需同步修订。
