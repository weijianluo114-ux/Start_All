# Q-001 · 脚本类程序无法按镜像名判定

- **状态**：已知限制（暂不处理）
- **提出日期**：2026-10-19
- **关联**：REQ-002、FEAT-003

## 现象

「关闭所有程序」通过进程镜像名判断某个条目是否在运行。但 `.bat` / `.cmd` 条目的进程名是
`cmd.exe`，真正的业务进程是它的子进程，名字与脚本无关。

因此当脚本**不是**在本次启动器会话里启动时，无法判断"它现在是否在运行"。

## 可选的判定方式

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 按 `cmd.exe` 判定 | 检查是否有 `cmd.exe` | 会把用户所有命令行窗口都算作命中，`/im` 关闭时更会误杀 |
| B. 解析命令行 | WMI `Win32_Process.CommandLine` 里匹配脚本路径 | 需引入 WMI 查询，开销大；提权进程读不到 |
| C. 记录 PID 差集 | 启动前后 `tasklist` 求差集（当前实现） | 只在本次会话有效，重启启动器后丢失 |
| D. 跳过并提示 | 现状 | 用户可能疑惑"为什么没关掉" |

## 当前结论

采用 **D（跳过）+ 提示**：在确认框里计入"无法判定"的跳过项，结果汇总里说明条数。

理由：批量误杀所有 `cmd.exe` 的代价远大于"个别脚本关不掉"。用户若确需关闭，可在任务管理器手动处理，
或把脚本替换为带独立进程名的 `.exe` 封装。

## 后续可做

- 若用户确有需求，再考虑 B（WMI 命令行匹配），并可缓存结果，仅在用户显式点击时查询。
