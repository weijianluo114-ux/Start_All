# Q-002 · 文件夹无法合并到资源管理器的标签页

- **状态**：已定位（平台限制，非本项目缺陷）
- **提出日期**：2026-10-19
- **关联**：REQ-004（已回退）、FEAT-006（已下线）

## 现象

预设中放多个文件夹，点「一键启动」后每个文件夹各弹一个资源管理器窗口，
用户希望它们在**同一个资源管理器窗口的不同标签页**中打开。

## 测试环境

| 项目 | 值 |
|---|---|
| 系统 | Windows 11，Build **26200.9457**（25H2 稳定版） |
| `Explorer\Advanced\SeparateProcess` | `0`（"在单独的进程中打开文件夹窗口"已关闭，满足标签页前提） |
| 资源管理器标签页 | 已具备（存在标题为「data 和 1 个其他选项卡」的窗口） |

## 三项实测（全部否证）

### 1. 对照组：直接打开两个文件夹

用 `os.startfile(目录)` 依次打开 A、B：

```
WINDOW_COUNT 3 → 5
LFTEST_甲_2312 - 文件资源管理器
LFTEST_乙_2312 - 文件资源管理器
```

→ **两个独立窗口**，问题复现。

### 2. 设置 `OpenFolderInNewTab = 1`（官方推荐做法）

写入两个候选位置（各 `dword:1`），并广播 `SHChangeNotify(SHCNE_ASSOCCHANGED)` 与 `WM_SETTINGCHANGE`：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\OpenFolderInNewTab
HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced\OpenFolderInNewTab
```

重新打开丙、丁两个新文件夹：

```
WINDOW_COUNT 5 → 7
LFTEST_丙_2312 - 文件资源管理器
LFTEST_丁_2312 - 文件资源管理器
```

→ **仍是两个独立窗口**，设置无效。

### 3. Shell 动词 `opennewtab`

注册表中 `Folder\shell\opennewtab` 存在（`command` 为空，交给 explorer 处理）。
用 `ShellExecuteExW` 以 `lpVerb="opennewtab"` 打开戊文件夹：

```
ShellExecuteExW(opennewtab) -> True, last_error = 0
WINDOW_COUNT 7 → 8
LFTEST_戊_2312 - 文件资源管理器
```

→ 返回值成功，但**开的是新窗口**，不是已有窗口的新标签。

## 根因

微软官方文档（Windows Insider 博客 / ElevenForum 汇总）：

- Build **22635.4580**（Beta）首次引入"从资源管理器外部打开文件夹时进入已有窗口的新标签页"；
- Build **22635.4800** 因问题**暂停**；
- Build **26200.5562**（Dev）**恢复**推送；
- Build **26220.7262** 起**再次暂停**，理由是"工作不正常"；
- 截至 2026-04，该功能**仍未进入稳定版**。

因此本机（26200.9457 稳定版）虽然资源管理器自带标签页，但"外部打开→并入标签"这条代码路径被特性开关关闭，
`OpenFolderInNewTab` 这个注册表值**没有消费方**，写了也不生效。这解释了第 2 项实测的失败。

## 结论

**在资源管理器内实现多标签打开，没有任何可脚本化的接口。** 可行路径只有三类：

| 方案 | 是否资源管理器 | 说明 |
|---|---|---|
| 等待微软恢复推送 | ✅ | 不可控，稳定版尚无时间表 |
| **ExplorerTabUtility**（开源） | ✅ | 22H2+ 可用，后台把新开的资源管理器窗口收进已有窗口的标签；需用户自行安装、需 .NET 9、常驻托盘 |
| UIA 模拟 `Ctrl+T` + 粘贴路径 | ✅ | 抢焦点、受输入法影响，Win10 无标签页，脆弱，**不采用** |

## 本项目处置

- v1.5.0 曾用 Qt 自建多标签窗口（方案 D）绕过限制，但**不是资源管理器**，不符合用户要求；
- **v1.6.0 已整体回退**，文件夹重新交由系统资源管理器逐个打开；
- 是否接入第三方工具（检测 + 提示）**未实现**，等用户决定。

## 复现方法

1. 打开两个临时目录并观察窗口数量（`EnumWindows` + `ClassName == "CabinetWClass"`）；
2. 写 `OpenFolderInNewTab=1` 后 `SHChangeNotify`，再打开两个新目录观察；
3. 用 `ShellExecuteExW(verb="opennewtab")` 打开目录观察；
4. 测试完成后删除该注册表值（原本不存在），并关闭测试窗口。

判定标准：桌面出现 `CabinetWClass` 窗口数量是否增加。
若两个目录只增加 0~1 个窗口且标题含「N 个其他选项卡」，说明命中了标签页；否则为独立窗口。
