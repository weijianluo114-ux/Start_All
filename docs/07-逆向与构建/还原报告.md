## 一、结论

**该程序不属于“原生机器码程序”，因此不需要走传统的 PE 反汇编路线。**

`一键多启.exe` 是 **PyInstaller onefile 打包的 Python 3.12 应用**。它的全部业务逻辑以 CPython 字节码（`.pyc`）形式完整保存在自身的归档区中，而不是编译为 x86-64 机器指令。因此逆向的正确入口是“拆 PyInstaller 归档 → 提取字节码 → 重建源码”，其可恢复程度远高于传统二进制逆向：**变量名、函数名、常量、字符串、甚至源码行号都保留在字节码里**。

## 三、还原方法

### 3.1 工具链选择

传统路线（`pycdc` / `uncompyle6` / `decompyle3`）在本环境不可行：

- `uncompyle6` / `decompyle3` 最高只支持到 3.8，面对 3.12 直接拒绝；
- `pycdc`（Decompyle++）需本地编译，而本机无 MSVC/MinGW/CMake 工具链；
- PyPI 源不可达（`files.pythonhosted.org` 连接失败），无法安装 `xdis` 等跨版本反汇编库。

因此采用**「精确版本运行时 + 自研解析 + 逐函数重建 + 字节码回归校验」**方案：从国内镜像取来 **CPython 3.12.10 embeddable**，使 `marshal.loads` 与 `dis` 在**完全对口的字节码版本**下工作——这是全部后续准确性的前提（3.13 的 opcode 编号与 3.12 不同，跨版本反汇编会得到错误结果）。

### 3.2 七个步骤

| 步骤 | 做法 | 脚本 |
|---|---|---|
| 1 | 定位并解析 CArchive cookie（`magic + 4×uint32 + pylibname[64]`），按 TOC 逐条解压（raw deflate）导出 154 个条目 | `pyi_extract.py` |
| 2 | 解析 `PYZ.pyz`（`PYZ\0` + magic + toc_offset），导出 180 个模块并清点，确认业务代码只有 1 个脚本 | `pyz_extract.py` |
| 3 | `marshal.loads` 加载主脚本，递归展开 code object 树，输出「签名 + 常量表 + 名字表 + 完整反汇编（含异常表）」清单（4,349 行） | `dump_code.py` |
| 4 | 依据反汇编逐函数重建源码：用 `co_consts` 反推全部字符串字面量与数据结构，用 `co_names` 反推属性/方法调用链，用 `MAKE_FUNCTION` 的 flags 反推默认参数与类型注解，用 `ExceptionTable` 反推 `try/except/finally` 嵌套层级 | 手工 |
| 5 | 用 3.12 重新编译还原源码，与原始 code object **逐函数递归比对**（签名 / 局部变量 / 常量 / 指令流，跳转目标归一化为指令序号），按差异定点修正 | `compare.py` |
| 6 | 依据 `co_lines()` 的原始行号标注，在函数定义前增删空行，使全文语句行号对齐 | `align_lines.py` |
| 7 | 用**exe 内解包出的 PyQt5 二进制** + 3.12.10 运行时真实加载还原源码，创建窗口并验证业务逻辑 | `smoke_test.py` |

### 3.3 迭代修正的三个典型例子

反编译不是“抄一遍”，下面三处差异只有靠回归比对才能发现：

1. **`not x in y` 与 `x not in y` 的区别**：原程序在 `remove_selected` / `terminate_all_and_exit` 中写作 `not ... in ...`（旧式写法），编译后是 `CONTAINS_OP 0` + `POP_JUMP_IF_TRUE`；而 `x not in y` 编译为 `CONTAINS_OP 1` + `POP_JUMP_IF_FALSE`。两者语义相同但字节码不同。
2. **`remove_selected` 的两个独立守卫**：我最初写成 `if not A or not B: continue`（1 个跳回），原始版本是两个分开的 `if ...: continue`（2 个跳回），指令数 52 vs 53——差异由此暴露并修正。
3. **`launch_program` 的常量分配顺序**：`co_consts` 中 `'xdg-open'` 排在 `None` 之前，说明原作在 `elif/else` 之后是**单一出口的 `return None`**，而不是每个分支各写一个 `return`。仅凭反汇编文本看不出来，靠常量表下标才定位。

## 五、核心逻辑（答辩要点）

**1. 配置持久化**
路径 `%LOCALAPPDATA%\MultiLauncher\launcher_presets.json`，结构为：

```json
{
  "last_used": "默认方案",
  "presets": {"预设名": ["C:\\path\\a.exe", "..."]},
  "settings": {"auto_launch": true},
  "global_macro": [{"type": "move", "x": 1, "y": 2, "time": 0.12}]
}
```

`load_config` 具备**向后兼容迁移**能力：条目既可以是字符串，也可以是 `{"path": ...}` 字典，两种都会归一化为字符串列表。`json.dump(..., indent=2, ensure_ascii=False)`，中文不会转义。

**2. 启动策略（`launch_program`）** 按平台与扩展名分流：
- `.exe/.bat/.cmd/.com` 且 Windows：`.bat/.cmd` 以脚本所在目录为 `cwd` 并加 `CREATE_NEW_CONSOLE`（避免子进程随启动器退出）；其余用临时目录作 `cwd`；
- `.lnk` 先经 `WScript.Shell.CreateShortCut().TargetPath` 解析真实目标，解析失败则回退原路径；
- 非可执行扩展名且 Windows：`WScript.Shell.Run(target, 1, False)`，成功则用 `ShellProc` 伪对象包装 PID（模拟 `Popen` 的 `pid/wait/kill` 接口）；失败回退 `os.startfile`；
- macOS / Linux：`open` / `xdg-open`。

**3. 批处理的子进程捕获**：`.bat/.cmd` 直接启动拿到的是 `cmd.exe` 的 PID，业务进程是它的子进程。原作的做法是记录启动前后的 `tasklist` PID 差集（`before`/`after`，中间 `sleep(2)` 等进程起来），把差集作为 `extra_pids` 一并存入 `launched_items`。

**4. 并发与中断**：`launch_all` 置 `_launching` 防止重入，工作线程用 `threading.Lock` 保护 `launched_items`，`_stop_launch` 作为中断标志；`_launch_worker` 整体包在 `try/finally` 中，`finally` 里经 `QTimer.singleShot(0, ...)` 回到主线程恢复按钮状态——这是跨线程更新 UI 的正确做法。

**5. 终止策略（`terminate_all_and_exit`）** 四级：`taskkill /f /t /pid <主PID>`（含进程树）→ 对 `extra_pids` 逐个 `taskkill /f /t /pid` → `taskkill /f /im <镜像名>` 兜底 → 对 `special_kill_map` 里登记的“关不掉的伴生进程”再补刀（默认 `start_without_steam.bat` → `VTube Studio.exe`）。每一步都 `try/except` 吞掉异常，保证清理不中断。

**6. 全局宏录制 / 回放**：`pynput` 的 `Listener` 采集 `move/click/scroll` 事件，时间戳为相对 `perf_counter()` 的偏移；回放时按 `delta = t - last_time` 逐事件 `sleep`，用 `MouseController` 的 `position/press/release/scroll` 复现。ESC 由独立的 `KeyboardListener` 捕获以停止录制。

## 六、保真度与残余差异

### 6.1 等价性验证方法

`compare.py` 对 49 个 code object 逐一比对五项：函数签名与 flags、局部变量表（含 cell/free vars）、`co_names`、`co_consts`（递归）、指令流（`opname` + 归一化参数，跳转目标换算为指令序号）。**任何语义改动都会导致指令流分叉，无法通过校验**——这比“看起来一样”要可靠得多。

最终：**3315 条指令全部一致，0 个函数存在差异。**

### 6.2 唯一的编码级差异（已归一化）

原始二进制在 2 处使用 `CONTAINS_OP 0 (in)` + `POP_JUMP_IF_TRUE` 表达否定判断；本机 3.12.10 编译同义源码产出 `CONTAINS_OP 1 (not in)` + `POP_JUMP_IF_FALSE`。我做了穷举实验（`not in` / `not x in y` / `not (x in y)` / `if-else` 四种写法），3.12.10 一律折叠为后者，说明这是**编译器补丁版本之间的编码差异**，与原源码写法无关，语义完全等价（校验器已按语义归一化后计为一致）。

### 6.3 不可恢复项（客观限制）

| 项目 | 状态 |
|---|---|
| 变量名 / 函数名 / 类名 / 参数名 | **完整恢复**（保存在 `co_varnames` / `co_names`） |
| 全部字符串字面量、数字、数据结构 | **完整恢复**（`co_consts`） |
| 语句顺序、控制流、异常结构 | **完整恢复**（指令流 + `ExceptionTable`） |
| 每个语句的源码行号 | **完整恢复**（`co_lines()`） |
| 注释、docstring 之外的说明文字 | **不可恢复**（不进入字节码） |
| 原始空行布局、括号与换行风格、f-string 书写形式 | **不可恢复**（不影响语义），已按行号对齐用空行占位 |
| `logo.ico` | 已从归档中原样提取（370 KB） |
| `version.txt` | 原名未随包携带，已按 PE 版本资源重建 |

> 因此 `launchforge.py` 中存在几处连续多行空行，它们对应原文件里被剥离的注释区——这是“保持行号对齐”与“不虚构注释”之间的取舍结果。
