# 构建与发布

## 环境

| 项目 | 值 |
|---|---|
| 解释器 | CPython 3.12 / 3.13 均可（发布版用 3.12，与原始程序一致） |
| PyInstaller | 6.x |
| PyQt5 | 5.15.x（含 PyQt5-Qt5） |
| pywin32 | 300+ |
| pynput | 1.7+ |
| 镜像 | `https://mirrors.aliyun.com/pypi/simple/`（官方源在国内常不可达） |

> 原始 exe 用 CPython 3.12 打包（包内 `python312.dll`）。用 3.12 重建体积最接近原始（差约 0.3%）。
> CI 固定 3.12，本地其他版本也能正常运行，仅包内 DLL 版本不同。

## 目录约定

| 路径 | 作用 |
|---|---|
| `src/launchforge.py` | 唯一源码入口，`APP_VERSION` 也在这里 |
| `assets/logo.ico` | 图标，打包时以 `--add-data` 嵌入 |
| `scripts/build.bat` | 一键构建（自动读版本号 + 重建快捷方式） |
| `scripts/update_shortcut.py` | 重建桌面快捷方式（由构建脚本调用） |
| `version.txt` | 写入 exe 的 VERSIONINFO |
| `dist/` | 构建中间产物（已 gitignore） |
| 仓库根 `LaunchForge_vX.Y.Z.exe` | 当前可用的测试版（已 gitignore，仅本地） |

## 打包命令

```bat
scripts\build.bat
```

脚本会从 `src\launchforge.py` 解析 `APP_VERSION`，产出 `dist\LaunchForge_vX.Y.Z.exe`，
复制到仓库根目录，随后重建桌面快捷方式、删除根目录中的旧版本 exe。

等价的手工命令（在仓库根执行）：

```bat
python -m PyInstaller --noconfirm --onefile --windowed ^
    --icon=assets\logo.ico ^
    --add-data "assets\logo.ico;." ^
    --version-file=version.txt ^
    --name LaunchForge_v1.6.1 ^
    src\launchforge.py
```

| 参数 | 作用 | 漏了会怎样 |
|---|---|---|
| `--onefile` | 单文件，运行时解压到 `%TEMP%\_MEIxxxx` | 变成 `--onedir` 的文件夹形态 |
| `--windowed` | GUI，不弹控制台（等价 `--noconsole`） | 多一个黑色 cmd 窗口 |
| `--add-data "assets\logo.ico;."` | 图标进包，供 `sys._MEIPASS` 读取 | 窗口图标缺失（代码有 `exists` 保护，不崩） |
| `--icon=assets\logo.ico` | 写入 exe 文件图标 | 资源管理器显示默认图标 |
| `--version-file=version.txt` | 写入 VERSIONINFO | 文件属性里没有产品名/版本号 |
| `--name` | 产物名 | 决定 exe 文件名与 `.spec` 名 |

Windows 上 `--add-data` 的分隔符是**分号** `源;目标`（Linux/macOS 是冒号）。

## 发布流程（单分支覆盖式）

仓库只保留一条主线 `main`，每次改动直接提交覆盖，需要回退时用 `git revert` / 检出历史。

1. 改代码，跑 `tests/` 里的回归脚本。
2. 同步三处版本号：`src/launchforge.py` 的 `APP_VERSION`、`version.txt`、`CHANGELOG.md`。
3. 本地 `scripts\build.bat` 构建并自测（见文末验证方法）。
4. 提交并推送：
   ```bat
   git add -A
   git commit -m "release: v1.6.1"
   git push
   ```
5. 打标签并推送：
   ```bat
   git tag v1.6.1
   git push origin v1.6.1
   ```
6. GitHub Actions（`.github/workflows/build.yml`）在 tag 推送后自动：
   在 `windows-latest` 上安装依赖 → 构建 → 校验产物 → 上传 artifact → 创建 Release 并附上 exe。

**二进制不进仓库**：`*.exe` 已在 `.gitignore` 中，历史版本只存在于 GitHub Releases；
本地仓库根目录仅保留当前可用的测试版。

> 产物统一用 **ASCII 文件名** `LaunchForge_vX.Y.Z.exe`（本地与 CI 一致）。
> 原因：GitHub Actions 处理非 ASCII 文件名时会丢字符（v1.6.1 首次发布曾得到 `_v1.6.1.exe`），
> 且 `.bat` 里的中文会因代码页不同而破坏解析。中文名只保留给桌面快捷方式（`一键多启.lnk`）。

## 产物命名约定

| 文件 | 含义 |
|---|---|
| `LaunchForge_vX.Y.Z.exe` | 当前版本，本地根目录只保留这一个（与 Release 资产同名） |
| `reference/一键多启_original_v1.0.0.exe` | 反汇编还原所依据的**原始程序**，仅存档、不提交（`reference/` 已 gitignore） |

历史版本（v1.3.0 / v1.4.0 / v1.4.1 / v1.5.0 / v1.6.0 等）已清理，需要时从 Release 或 git 历史获取。

## 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 覆盖 exe 报 `Device or resource busy` | 有实例正在运行 | 关掉实例后重试，或改用新文件名（BUG-001） |
| 首次启动慢 1–3 秒 | onefile 需先解压 | 正常；如需秒开改用 `--onedir` |
| 杀软报毒/拦截 | onefile 自解压行为易被启发式判定 | 加白名单，或改用 `--onedir` + 签名 |
| `print` 的警告看不到 | `--windowed` 无控制台 | 调试期临时用 `--console` 打包 |
| 缺图标/缺资源 | 用 `sys._MEIPASS` 读的文件没 `--add-data` | 补 `--add-data` |
| 关闭时闪一堆黑框 | 子进程未加 `CREATE_NO_WINDOW` | 见 BUG-003，统一走 `hidden_subprocess_kwargs()` |
| 目标机跑不起来 | 打包机与目标机位数不同 | 同为 64 位；极老系统需 32 位 Python |

## 验证构建是否可用

```bat
set LOCALAPPDATA=D:\tmp\lf_verify
一键多启_v1.6.1.exe
```

看到标题为「一键多启」的窗口、且任务管理器里出现两个同名进程（bootloader + 应用），即为正常。
用隔离的 `LOCALAPPDATA` 可以避免读到真实配置、误启已有预设。

## CI 说明

- 触发条件：推送 `v*` 标签，或在 Actions 页面手动 `workflow_dispatch`。
- 手动触发只产出 artifact，不创建 Release（`if: startsWith(github.ref, 'refs/tags/')`）。
- 资产名：`LaunchForge_vX.Y.Z.exe`（ASCII，见上方说明）。
- Release 使用 `generate_release_notes: true`，由 GitHub 依据提交与 PR 自动生成说明；
  如需手工补充，可在 Release 页面编辑。
