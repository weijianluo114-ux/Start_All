## v1.2.0 · 取消「打开即启动」（REQ-001）

**问题**：原程序记住 `last_used` 预设，并在主窗口构造完成后
`QTimer.singleShot(300, self.auto_launch_last_preset)` 自动启动。

**改法**：整条通路移除，而不是加开关。

| 位置 | 原内容 | 现内容 |
|---|---|---|
| `__init__` | `self.auto_launch_enabled = True` | 删除 |
| `__init__` | 「设置」菜单 + `QAction('启动程序自动启动列表应用')` | 整段删除 |
| `__init__` 末尾 | `if self.auto_launch_enabled: QTimer.singleShot(300, ...)` | 删除 |
| 方法 | `toggle_auto_launch` | 删除 |
| 方法 | `auto_launch_last_preset` | 删除 |
| `save_config` | `settings.auto_launch` | `settings` 置空对象 |
| `load_config` | 读取 `settings.auto_launch` | 不读取，旧值忽略 |
| 导入 | 含 `QAction` | 移除 |

兼容性：旧配置里的 `"auto_launch": true` 被完全忽略，下次保存时自动消失，无需手工清理。

**验收**：`test_step1_no_autolaunch.py`，并用 `LF_SRC=baseline` 做对照——基线会误启动，改造后不会。

## v1.3.0 · 关闭所有程序前确认 + 运行检测（REQ-002）

**问题**：旧按钮直接对 `launched_items` 执行 `taskkill /f /t` 并紧接着 `close()`：
无确认、只覆盖本次会话启动的进程、对未运行条目也照发命令。

**改法**：`terminate_all_and_exit()` → `close_all_programs()`，拆成职责单一的方法。

| 方法 | 职责 |
|---|---|
| `_get_process_map()` | `tasklist /fo csv /nh` → `{镜像名小写: {pid…}}` |
| `_close_targets(paths)` | 列表条目 → `(原路径, 镜像名)`；文件夹/脚本类镜像名为 `None` |
| `_find_launched(path)` | 按规范化路径找回本次启动记录（拿精确 PID） |
| `_kill_target(path, image)` | PID → 镜像名 → `special_kill_map` 三级关闭 |
| `_taskkill(args)` | 统一封装 `taskkill`，返回退出码是否为 0 |

**交互**：确认框（默认「否」，列出程序名）→ 点「是」才执行 → 二次校验 → 结果汇总 → **不退出启动器**。

**判定顺序**：本次启动且 PID 在 → 运行中；`None` 镜像名 → 跳过；等于启动器自身 → 跳过；
在进程快照里 → 运行中；否则跳过（未运行）。

**验收**：`test_step2_close_all.py`（真实进程 + 假弹窗），覆盖"取消/确认/全部未运行/不退出"四条路径。

## 附：产物命名变更

原计划固定输出 `一键多启_rebuild.exe`，因覆盖正在运行的实例会触发文件占用（BUG-001），
