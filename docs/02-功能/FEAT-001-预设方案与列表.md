# FEAT-001 · 预设方案与程序列表

- **状态**：可用
- **首次版本**：v1.0.0（还原基线）
- **关联需求**：REQ-003（扩展文件夹）
- **代码位置**：`src/launchforge.py` → `LauncherWindow` 的 `presets` / `current_preset_name` 及 `save_config`、`load_config` 等

## 它做什么

把不同场景（"直播"、"开发"、"游戏"）要启动的程序分组保存，互不干扰，切换即换一套列表。

## 入口

| 入口 | 操作 | 结果 |
|---|---|---|
| ➕ 新建 | 输入名称 | 新增空预设并切换过去 |
| ❌ 删除 | 确认 | 删除当前预设（至少保留一个） |
| 下拉框 | 切换 | 先保存当前列表，再载入目标预设 |
| 拖拽文件 / 文件夹 | 拖入窗口 | 追加到列表并写入当前预设 |
| 📂 添加程序 | 文件选择框（可多选） | 追加（自动去重） |
| 📁 添加文件夹 | 目录选择框 | 追加（自动去重），见 FEAT-005 |
| ✏ 输入路径 | 手动输入 / 粘贴 | 校验存在性后追加，见 FEAT-005 |
| 🗑 删除选中 | 列表多选 | 从列表与预设中同时移除 |

## 行为细节

- **自动保存**：任何改动都会落到 `%LOCALAPPDATA%\MultiLauncher\launcher_presets.json`，无"保存"按钮。
- **去重**：`add_to_list` 按 `normcase(normpath())` 比对，`C:/a` 与 `C:\a` 视为同一条。
- **失效路径**：载入预设时不再丢弃，而是显示为 `⚠ 名称`；启动时跳过，配置里保留（避免 U 盘未插时条目被永久删除）。
- **切换预设**：`on_preset_changed` 先 `save_current_list_to_preset()` 再载入新预设，并 `save_config()`。

## 数据结构

```json
{
  "last_used": "默认方案",
  "presets": { "预设名": ["C:\\path\\a.exe", "C:\\path\\某个文件夹"] },
  "settings": { "last_folder": "C:\\path" },
  "global_macro": []
}
```

条目为**路径字符串**，程序 / 文件 / 文件夹混排，类型在运行期用 `os.path.isdir()` 判定；
`load_config` 兼容历史格式 `{"path": "..."}` 并自动归一化。

## 已知限制

- 重名预设会被 `new_preset_dialog` 拦截；预设名不支持重命名（可新建后删除旧的）。
- 列表不支持拖动排序（启动顺序 = 加入顺序）。
