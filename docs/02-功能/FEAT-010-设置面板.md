# FEAT-010 · 设置面板（开机自启动）

- **状态**：可用（v1.10.0）
- **入口**：主界面圆盘右侧下角「设置」胶囊
- **关联**：REQ-010、FEAT-009（胶囊布局）
- **代码**：`autostart_state()` / `set_autostart()` / `heal_autostart_path()` / `ToggleSwitch` / `SettingRow` / `SettingsDialog`

## 它做什么

一个 400×224 的小面板，目前只有一项：**开机自启动**。开启后，登录 Windows 时自动打开启动器。

注意：开启自启动**不会**自动启动列表内的条目。启动器只显示界面，启动动作仍必须由用户点击圆盘左半 —— 这是 REQ-001 的既有约定，本次没有改变。

## 界面结构

```
┌─ 设置 ──────────────────────────────┐
│  设置                                │
│  ┌───────────────────────────┐  ┌─┐ │
│  │▎开机自启动                 │  │◉│ │   ← 整行可点，右侧胶囊开关
│  │ 登录 Windows 后自动打开启动器│  └─┘ │
│  │ 不会自动启动列表内的条目。   │      │
│  └───────────────────────────┘      │
│  未启用 · 开启后随 Windows 登录启动   │
│                          [ 关闭 ]    │
└──────────────────────────────────────┘
```

| 区域 | 行为 |
|---|---|
| 设置卡片 | 整行可点；悬停时底色提亮、边框转金、左侧竖条加长、开关出现发光环 |
| 开关 | 52×28 胶囊，140ms 缓动；支持鼠标点击与空格 / 回车 |
| 提示行 | 显示状态与程序名；完整命令行在 tooltip 里 |
| 关闭 | 不保存任何东西，只是关窗（改动早已即时生效） |

## 注册表实现

```
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
  LaunchForge = "E:\...\LaunchForge_v1.10.0.exe"
```

| 函数 | 职责 |
|---|---|
| `autostart_command()` | 生成命令：frozen 用 exe 路径，源码运行用 `pythonw` + 脚本路径 |
| `read_autostart()` | 读值，未设置返回 `''`（`FileNotFoundError` 视为未设置，不是错误） |
| `autostart_state()` | 返回 `(是否启用, 命令, 是否指向当前程序)` |
| `set_autostart(flag)` | 写入 / 删除，返回 `(成功, 失败原因)` |
| `heal_autostart_path()` | 目标文件已不存在时改写为当前程序 |

三个可测参数 `key_path` / `value_name` 允许指向独立沙箱键，测试因此不必碰真实 Run 键。

## 升级自愈

因为产物名带版本号、升级后旧 exe 会被清理，所以启动时检查一次：

| 情况 | 处理 |
|---|---|
| 未开启 | 不动 |
| 开启且指向当前程序 | 不动 |
| 开启但指向的文件**不存在** | 改写为当前程序，日志记一条 |
| 开启且指向另一份**存在**的副本 | 不动（不抢占用户的另一份安装） |

## 已知限制

- **只支持 Windows**。其它平台该行会置灰并显示禁止光标；`set_autostart` 返回失败说明。
- **不写"启动参数"**：仅支持"登录即显示界面"。若将来需要"登录后静默到托盘"，要先有托盘能力。
- **不检测登录项是否被系统禁用**：任务管理器 → 启动 里被手动禁用时，注册表值仍然存在，
  本面板会显示"已启用"。Windows 未提供查询该开关状态的稳定接口。
- 安全软件可能拦截注册表写入；此时会回滚开关并弹出原因，不会静默失败。
