# FEAT-013 · 圆盘放大与盘面文字

- **状态**：可用（v1.13.0）
- **范围**：主窗口顶部启停圆盘（`TaijiLaunchButton`）的尺寸、盘面字体与文字排布
- **关联**：REQ-013、REQ-006、REQ-011、REQ-012
- **代码**：`TaijiLaunchButton.DIAMETER` / `_pick_text_family()` / `_fish_span()` /
  `_text_layout()` / `_paint_text()` / `_paint_char_glow()`

## 规格

| 项 | 值 |
|---|---|
| 盘面直径 | 184（v1.12.0 及之前是 160） |
| 控件尺寸 | 216×216（四周各 16px 留给落影） |
| 盘面字体 | 幼圆（`YouYuan`）→ MiSans → 界面 display 字体 |
| 字号 | `R × 0.33 × 全局倍率`，再逐档缩小以避开盘沿（当前落在 29px） |
| 行距 | 字的 1.00 倍（竖排两字） |
| 字芯 | 暖金 `#FFD79A`，竖向渐变（上浅下深） |
| 描边 | `#5B2C00` × 1.25px（8 个方向） |
| 悬停 | 字芯 → `#FFF0C4`，描边转暖 `#8A4A12`，外圈柔光 150 alpha |
| 禁用 | 字芯 `#6F6F6F`，去掉描边改用 1px 白亮边 |

## 文字为什么不会再跨缝

S 形边界在 `y = cy` 处会从 `cx + 0.5R` 跳到 `cx - 0.5R`，所以"固定圆心 + 固定宽度"的
文字框只要下沿过中线，就有一半压到另一条鱼上（v1.12.0 的 17px 就是这样）。

现在改成三步：

1. **算可用区间**：`_fish_span(side, y0, y1)` 在字的纵向区间内取 9 条扫描线，
   用解析式求出每一行的鱼身左右边界，再取交集 —— 得到"这一段鱼身最窄处"的宽度；
2. **整块定中线**：两字的区间再取交集，把竖列放在这个公共区间的正中间（不逐字居中，避免错开）；
3. **让位与收缩**：右界压到鱼眼外 4px 以内；若字盒四角仍离盘沿不足 5px，就把字号减 1 重算，
   直到满足为止。

结果：11px / 13px / 17px 三档全局字号下，字盒都完整落在本侧鱼身内，且不压鱼眼。

## 悬停时的文字高亮

```
强度 0 → 1（与鱼身提亮共用同一个 130ms 补间）
  字芯   #FFD79A → #FFF0C4（更亮）
  描边   #5B2C00 → #8A4A12（转暖）
  柔光   8 个方向的低透明度副本，alpha 0 → 150，扩散 0.9 → 3.5px
```

柔光不用 `QGraphicsDropShadowEffect`（中文会发虚，v1.11.0 的教训），
而是同一个字画 8 遍浅色副本再压字芯，代价是每帧多 16 次 `drawText`，
但只发生在悬停那一半、且不触发布局。

## 为什么不跟随「设置 → 字体搭配」

盘面是插画，不是正文。用户在设置里选「书卷衬线」是想让正文更文气，
不代表要让两颗按钮变成宋体。因此盘面固定走圆体候选链，缺字体才退到界面字体。

全局字号只影响盘面文字 ±8%，且最终还要服从盘沿约束——实际三档都收敛到 29px，
即"圆盘文字大小稳定，界面文字可调"。

## 性能

布局结果按 `(直径, 全局倍率, 字族)` 缓存：

```python
self._text_cache_key = (self._d, round(FontPrefs.scale(), 2), self._text_family)
```

悬停动画每帧只改画笔颜色与光晕强度，不重算几何、不重建字体。

## 已知限制

- 幼圆只有 Regular 一档，Bold 由系统合成，笔画比真粗体略钝；
- 只有两个字的竖排，没有做"沿 S 曲线旋转"的排法；
- 盘面字号不随窗口缩放（圆盘尺寸是固定的 184）。
